Yeni Şikayet

Virgülle veya alt alta yazabilirsin. Tam URL yapıştırırsan otomatik domaine indirgenir.
Netcraft formundaki "kim bildiriyor" alanını ve giden maillerin Reply-To adresini belirler. Boş bırakırsan markanın kendi maili kullanılır (ör. betsat için support@betsat.com).
Bu, tam bir şikayet mailinin GÖNDERİLECEĞİ adrestir — host otomatik tespit edilemediğinde veya bildiğin bir adrese ekstra göndermek istediğinde kullan.
▸ GitHub bağlantı ayarları
PAT şu iznlerle, fine-grained token olarak oluşturulmalı: Actions: Read and write (tetiklemek için) ve Contents: Read and write (gerçek sonuçları okumak ve panelin yazdığı sonuç dosyasını görebilmek için) — süresi olan, tek repo'ya kısıtlı bir token kullan. Bu sayfa token'ı hiçbir sunucuya göndermez, sadece GitHub API'ye doğrudan tarayıcından istek atar.

Gönderim Geçmişi

Henüz gönderim yok. İlk şikayetini gönderdiğinde burada görünecek.
GitHub Actions'ta Görüntüle →
Panel, GitHub Actions workflow_dispatch event'ini tetikler ve ardından gerçek sonucu (mail atıldı mı, hangi host/registrar bulundu vb.) otomatik olarak çekip burada gösterir. Aynı bilgi ayrıca Telegram'a da düşer. Geçmiş bu tarayıcıda kalıcı olarak saklanır (son 100 kayıt).
▸ Bilinmeyen Cluster Takibi
Gerçek sonuçlarda "host cluster tespit edilemedi" çıkan domainler burada otomatik birikir. Listeyi kopyalayıp Claude'a "manual_complaint.py'ye ekle" diye gönder, sonra listeyi temizle.
Henüz bilinmeyen cluster yok.
▸ Bilinen Cluster / Host Referansı
Salt okunur referans — manual_complaint.py'deki CLUSTER_MAP'in bir kopyası. Kod güncellendiğinde bu liste elle senkronize edilmeli, otomatik değil.
